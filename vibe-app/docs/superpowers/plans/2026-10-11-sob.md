# School Operating Budget (SOB) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the PPMP with a per-quarter School Operating Budget built from the AIP, whose approval creates the quarter's Budget allotments and which feeds the APP.

**Architecture:** New `sob_plans` and `sob_items` tables, a `SobService` holding every rule (create, items, totals, over-AIP warning, approve with allotments), a thin `SobController`, an SOB panel on the Planning page, an official print view, and `generateApp` reading SOB items. The PPMP screens and routes are removed last; PPMP tables and data stay.

**Tech Stack:** Laravel 13, PHP 8.4, SQLite, PHPUnit 12 (`php artisan test --compact`), Blade with plain JavaScript, Pint (`vendor/bin/pint --dirty --format agent`).

**Spec:** `vibe-app/docs/superpowers/specs/2026-10-11-sob-design.md`. Read it with this plan.

## Global Constraints

- No new Composer or npm package. Additive migrations only: no table or column dropped or renamed; PPMP tables and rows are left as they are.
- Flow: SIP -> AIP -> SOB -> APP -> Purchase Request. One SOB per (`school_id`, `fiscal_year`, `quarter` 1 to 4, `fund_source` default `MOOE`). Statuses `draft` and `approved`; an approved SOB is locked.
- `amount = round(frequency * quantity * unit_cost, 2)`, computed on the server. Frequency > 0 (default 1), quantity > 0, unit required (max 50), unit cost >= 0, particulars required (max 255).
- An SOB needs an approved AIP for the school and fiscal year, and an open fiscal year (`FiscalYearService::assertOpen`). Business-rule failures throw `ValidationException` with key `planning` (the Planning page convention, `PlanningController::requires`).
- An item's `aip_activity_id` must belong to the SOB's AIP and its `chart_of_account_id` to the SOB's organization.
- Over-AIP spending on an activity is a **warning only** (the page shows both amounts); it never blocks saving or approving.
- Approve allotments key: (SOB `fund_source`, `chart_of_account_id`, the activity's `AipKra.program`); match an existing `BudgetAllocation` by `aip_id`, `source_of_fund`, `chart_of_account_id`, `program`, `fiscal_year`; set its `q{N}_amount`, `amount` = sum of its four quarters; refuse (nothing saved) if the new `amount` is below its obligated amount from `BudgetService::matrix`. New lines: `office` = school name, `start_date`/`end_date` = the fiscal year, `created_by` = approver, `uacs_code`/`particulars` from the account, `budget_ref_no` from `DocumentNumberService::next($orgId, 'budget_allocation', 'BA', $year)`, remarks `From SOB FY {year} Q{N}`.
- APP item from an SOB item: `procurement_item` = particulars, `specifications` = the activity text, `quantity` = frequency x quantity, `unit`, `estimated_unit_cost` = unit cost, `estimated_total_cost` = amount, `fund_source` = SOB fund, `sob_item_id` set; never duplicated.
- Permission `planning.manage` to change anything; school scope as in `PlanningController::schoolIds()`; all text escaped in views.
- Tests use `RefreshDatabase`. Multi-line edits to existing files go through a Python script file (heredocs with apostrophes break in this shell); long files are written with the Write tool. Run `vendor/bin/pint --dirty --format agent` after PHP changes. Commit steps run only when the user has asked for commits; push and deploy only when asked. `docs/specs.md` and `CLAUDE.md` Phase text are protected: the owner decides in Task 7.

## Review Focus

- Decimal amounts: frequency 0.5 x quantity 3 x unit cost 33.33 rounds to 2 places; zero, negative or non-numeric frequency, quantity or cost is refused; the stored amount is never taken from the request.
- Approving the same SOB twice, or two requests at once: the second is refused inside the transaction and no allotment line is doubled.
- Q1 approved, then Q2: the line keeps Q1, gets Q2, and `amount` is the sum; an approval that would put an allotment below its obligated amount refuses and rolls back every other group of that approval.
- An item posted with another school's AIP activity id or another organization's account id is refused; another school's SOB cannot be opened, changed or printed.
- Generating the APP twice adds no duplicates and leaves PPMP-origin APP items untouched; a PR line drawing frequency x quantity from a SOB-based APP item passes the quantity and cost checks.
